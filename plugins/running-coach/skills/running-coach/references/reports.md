# 报告和提醒

输出应以图表为主：优先可浏览的完整多图 HTML 报告或适合分享的图片/PDF，配简洁文字解释与建议。图表数量由数据质量和阅读目标决定，不能为了丰富而虚构数据。指定周期使用用户时区的自然日、周、月、年；未完成周期标记“截至目前”，与完整上一周期区分。

## 图表语言

选择统一且适合内容的配色与排版：可用浅色运动仪表盘、深色赛季回顾或其他视觉风格，不固定模仿某张参考图。清楚显示单位、日期、来源和图例，确保手机上可读。图表选择、框架、交付和质量检查详见 [可视化指南](visualization.md)。

- 日报：当天运动卡片、单次分段或近期跑量图、恢复信息和次日建议。
- 周报：距离/次数/时长、每日跑量柱状图、近期趋势和强度分布（有数据时）、一条恢复建议。
- 月报：每周里程、训练频次和趋势；年报：每月里程及年度亮点。样本不足时隐藏不可支持的图。
- `scripts/render_report.py` 是不依赖第三方库的基础柱状图后备方案，不是默认或完整报告模板。将核实数值整理为 `examples/sample.json` 所示结构，运行 `python3 scripts/render_report.py input.json output.svg`。模板不读取 MCP；不得把样例当成用户数据。

## 定时任务

先手动完成一次报告并让用户看到效果。只有用户指定或同意的提醒、频率、时区和交付方式才创建；使用当前宿主提供的定时工具，不手写假任务。任务提示应要求每次重新读取数据、明确区间、检查登录与同步、生成报告并指出失败，不得假装发送成功。创建后反馈实际任务状态和下次时间；不支持时提供可复制的任务描述。定期提醒不是实时监测，不能保证精确发现训练结束或健康异常。

首次报告后主动提出可选的日报、周报或训练日提醒；询问用户希望哪些任务、何时运行、时区和训练安排，用户已说明的信息不再问。示例任务说明（替换方括号）：

> 每周一 [时间]（[时区]）读取 Garmin 和 RQrun 上一个自然周的数据，按 running-coach 生成图表周报、核对同步重复并给出简短恢复建议。若账户失效或数据不完整，说明原因和处理方法，不猜测数据。

每日训练提醒应读取近期训练、当天计划与可用恢复信息，提醒的时间由用户选择；没有计划或缺少恢复信息时明确说明，不推断用户必定要训练。月报、年报分别使用上一个完整自然月、自然年，除非用户另有指定。任务创建后复查任务清单，重复时更新已有任务或告知用户，避免多次创建。
