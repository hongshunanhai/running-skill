# 运动数据可视化指南

目标是让跑友先看到训练结论，再探索数据。选择图形和布局时参考运动报告的指标组织方式，但不要照搬单一截图或固定布局。数据不同，报告结构也应随之变化。

## 根据问题选图

| 问题 | 适合的展示 | 数据与解释要求 |
| --- | --- | --- |
| 本期训练了多少 | 总距离、时长、次数、平均配速的指标卡，附可比上期差异和小趋势 | 标明周期与单位；比较期不完整时说明；平均配速按总时间/总距离，口径需一致 |
| 跑量如何变化 | 按日/周/月柱状图，必要时叠加用户设定的目标线 | 零训练与缺失区分；目标只来自用户或真实计划 |
| 强度怎样分配 | 心率或配速区间的堆叠条形图、环形图 | 仅在区间定义和时间覆盖完整时计算百分比；注明平台、区间口径及未知部分 |
| 负荷和恢复怎样变化 | 训练负荷、体能/疲劳/状态或 HRV 的时间折线，必要时分面展示 | 标明数据来源、日期及单位；不同平台算法不可视作相同指标，缺值断线 |
| 单次跑步表现 | 分段配速柱形图、心率/配速时间曲线、步频或海拔折线 | 分段或采样来自活动详情；配速单位及较快方向清晰标注，避免不明双轴 |
| 不同平台为何不一致 | 并列条形图、差值卡或对照表 | 先确认是同一活动；列出各平台原值、单位、差异和可能的口径原因，不武断断言错误 |
| 步频、心率等如何关联 | 散点图或逐次标注的点图 | 点数和字段不足则展示原始记录，不用少量点推断因果或拟合趋势 |
| 一个月或一年何时跑步 | 日历热力图或月度跑量柱状图 | 缺失不是休息日；周期不完整、时区和颜色含义须明确 |
| 成绩或目标的变化 | 配速/成绩趋势线、PB 或目标差值卡 | 预测与实际分开展示；距离、成绩和预测来源可比时才比较 |

可以组合指标卡、趋势图、强度分布、对比图与简短结论，但按任务挑选最有意义的图，而不是机械堆满全部类型。来自 Garmin 的健康和训练指标、RQrun 的训练状态和强度可能缺失或采用不同算法；不要计算没有定义的 CTL、ATL、TSB 或恢复阈值。

## 框架和交付

- **Apache ECharts**：优先考虑交互式 HTML 多图仪表盘，适合柱状、折线、环形、散点与日历图混排；支持 Canvas 和 SVG。https://echarts.apache.org/en/
- **Plotly**：适合交互探索、悬停查看数据及 Python 绘图；需要静态图片时先确认导出依赖可用。https://plotly.com/javascript/basic-charts/ 、https://plotly.com/python/static-image-export/
- **Chart.js**：适合轻量的网页柱线与环形图；Canvas 应提供可访问的文字替代。https://www.chartjs.org/docs/latest/general/accessibility.html
- **D3 或原生 SVG**：当设计需要自定义图形、特殊布局或不依赖图表库时使用；常规图不必为使用 D3 而增加复杂度。https://d3js.org/

先检查宿主已有的库、浏览器和文件预览能力，再按用户要交互页面、分享图片或 PDF 选择方案。不要假设网络、CDN、浏览器、PNG 导出器可用；如需安装依赖遵循宿主权限。尽量将依赖打包或使用现有本地资源，避免 HTML 离线打开时白屏。训练和健康数据只写入用户选择的报告，不上传到第三方图表服务；交互 HTML 可能包含完整原始数据，分享前提醒用户检查。

优先生成完整 HTML 或经过验证的多页/长图；HTML 需要合理的移动端单列布局、宽屏可多列，支持清晰的打印样式和无交互时的数值可读性。用户要求 PNG/PDF 时用可用的本地渲染工具导出并核对；没有导出能力时如实交付 HTML 或 SVG。若图表框架不可用，先尝试宿主绘图能力或 MCP 的 `render_chart`，最后使用本包的基础 SVG 脚本；标注这是降级结果，不称其为完整多图报告。

## 视觉与核对

信息层次建议：标题与报告区间 → 核心指标 → 最有价值的 2–5 个分析图 → 训练建议与数据来源。可以改变顺序和图表数量；日报可更短，月报、年报可增加长期趋势。风格可以清爽、运动、科技或用户指定的品牌风格，配色、字体与留白保持一致；避免彩色装饰掩盖数据。

每张图给标题、单位、时间范围和必要图例；颜色之外用文字或形状区分系列。小屏幕下确保标签与标题不重叠，数值不会被裁切；长图适当分段。数据标签、百分比、日期和来源需和输入核对。缺值显示为空或“暂无数据”，不连成连续趋势；解释不确定性。打开生成的实际报告检查显示、图表、中文字体、对比度及导出效果，再交付；无法预览时明确说明没有完成视觉验证。

运动产品的数据组织可参考 [Garmin 报告](https://support.garmin.com/en-US/?faq=99CGXYuO9u7lywZQWn7B46&productID=73207&tab=topics) 和 [Strava Fitness & Freshness](https://support.strava.com/en-us/articles/15402032-how-fitness-freshness-is-calculated)，但不同来源的指标不应混同。
