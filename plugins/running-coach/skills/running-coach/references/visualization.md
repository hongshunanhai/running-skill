# 运动数据可视化指南

目标是让跑友先看到训练结论，再探索数据。报告质量不随数据量缩水：只有一天的数据也要成页，原则是"本期为主角，参照自动补"（近期同类活动、PB、预测主动拉取）。展示方式以两家平台的真实页面为蓝本（见下方实证分析），但不照搬截图。

## 质量底线（硬性要求）

**第一步：理解问题，选择数据**

| 场景 | 可选数据，按用户问题和实际可用性选择 |
| --- | --- |
| 单次/日报 | 活动详情、分段、心率区间、逐点数据、近期同类活动、PB、恢复数据 |
| 周/月/年 | 周期汇总及活动列表、历史对照、负荷、强度、跑力、PB 或预测 |
| 训练计划/备赛 | 目标赛事、时间、现有计划、训练历史、恢复、强度锚点和用户约束 |
| 自定义统计/复盘 | 聚焦用户指定指标、时间范围与对照条件，按需拉取明细 |

缺项标"暂无"并隐藏对应图，不许编造；需要双源对照时分别读取同区间数据。仅有一端可用时说明限制并使用可用数据。

**动态选图**：先明确用户要回答的问题，再用真实数据决定图表数量、粒度和形式。量的比较可用柱图，趋势可用折线，构成可用堆叠条或环形，计划可用时间轴或表格；少量数据用少量图，不为凑数量虚构数据或画空图。训练计划区分拟议与已完成，统计明确筛选条件和分母。

**文字预算**：每图配一行"所以呢"解读（这句写在图上）；结论块之外无成段分析；来源、区间、单位进页脚。

**交付前自检**：打开实际文件核对数值与接口一致、标签不裁切、颜色不依赖色觉、暗色可读、无空白图；无法渲染核验时明说。无法进行视觉核验时，检查脚本语法、图表初始化、数据与容器的对应关系、缺失值及占位符，并说明未做视觉核验；桩测不能证明实际布局正常。

**分享级出图**：固定色板（1 主色 + 2 强调 + 2 语义色）与字号层级，整页 ≤5 色。用户要转发时导出 PNG 长图或 PDF（宿主有 Chrome/Chromium 用 headless `--screenshot`，有 playwright/wkhtmltoimage 亦可），都没有就交 HTML 并说明；导出后核对中文字体与裁切。

## 设计规范（默认值，除非用户另有要求）

**视觉方向**：无论日报、周报、月报还是年报，都按用户选择的周期和数据组织内容；以跑步为主题设计有辨识度的首屏，突出本期最重要的结论与对照。使用明暗和强调色形成清晰对比，图表层级、字号与留白保持易读；配色是可调整的起点，不限制报告使用高对比的深色背景。数据变化不自动等于好坏，颜色必须有文字或形状辅助区分。

**动态与交互**：交互式 HTML 默认设计一处有辨识度的入场效果，并使用本地 JavaScript/ECharts 为相关图表提供平滑过渡、悬停或点击详情；效果服务于理解数据，不能遮挡或改变数值，避免循环闪烁。支持 `prefers-reduced-motion: reduce`，关闭非必要动画并立即显示最终数据；关键数据同时提供可读文本，保证触屏、键盘和静态展示可用。按实际视口检查标签、卡片、图例和表格，不以脚本能运行代替视觉检查。

- **图表库**：默认 Apache ECharts，且必须内联 skill 自带的 `assets/echarts.min.js`（`<script>` 直接嵌入报告 HTML），保证 file:// 双击可开、无网络也能渲染；禁止依赖 CDN。canvas 图表旁保留关键数字的文字版（指标卡与解读行已覆盖）。
- **版面**：围绕本次任务设计视觉层级与响应式网格；深浅背景均可，确保文字、图例和控件对比清晰。图表尺寸随内容调整，宽屏和手机均避免裁切、重叠或无意义留白。
- **色板**：主色深蓝 #2563EB；强调橙 #F97316（结论/达标）、绿 #10B981（良好/恢复）、红 #EF4444（风险/过量）、灰 #9CA3AF（参照/缺数据）。语义色只表达好坏，不混作系列色；负荷/状态图里的"疲劳""状态"线是系列不是语义，用系列色（如蓝/橙），恢复时长等纯量条用中性色。
- **数字可读性**：时长秒数 ≥60 一律换算成"分:秒"（如 20:41），配速用 `m'ss"`，界面不出现"1241 秒"这类原始值；悬停提示与图上标签同一规则。
- **饼/环标签**：标签设 `alignTo:'edge'` + `edgeDistance` 防裁切，0 值切片不显示标签；成对环形图（如双源区间口径）放整行卡，不放半宽卡——半宽卡装不下两组"区名+百分比"。
- **参考线不带长文字**：均值线、目标线的说明写在图的"所以呢"行，不在图上叠文字框；线端标签会压住柱子和折线，`label.show:false`。
- **坐标轴留白与单位**：按坐标轴标题、刻度和图例预留绘图区空间；在桌面和手机宽度检查它们与卡片标题、说明及其他图形不裁切、不重叠。单位也可放在图外说明中，但必须与坐标轴实际量纲一致。
- **反转轴必须声明方向**：配速秒数、反向排名等 `inverse` 轴，在副标题写明"越右越快/越左越快"；落笔前对照 `min/max/inverse` 配置核对一遍方向词，不许凭感觉写。
- **图形选择**：以数据和比较目的决定图形；对照值可用虚线或并排显示，不挤占主要数据。对每张图提供易懂的标题、单位、范围和一行解读。

## 平台页面实证分析（DOM 实测，2026-11）

以下内容来自对两家已登录页面的实际 DOM/AX 分析，是"专业长跑平台怎么展示"的参照标准。产出报告时对照检查：两家都有的展示维度，报告里不应缺席。

**RQrun 训练分析页（rq.run/user）**：模块化卡片纵向排列，每个模块可按时间窗切换。

| 模块（DOM class） | 展示内容 | 借鉴点 |
| --- | --- | --- |
| calendar_statistics | 周跑量/月跑量切换 + 运动类型过滤，柱状图 | 有助比较跑量时使用，可按数据和需求提供切换 |
| one_sentence | 每日一句 | 人格化点缀，可选用 |
| 训练趋势 training_trend | 跑力/负荷随日期折线 | 长期趋势一律折线 + 日期轴 |
| 跑步各强度区间 intensity_secs | 按配速区的时间占比，分组/堆叠柱 | 强度分布按时间口径堆叠 |
| 跑步各强度训练负荷 intensity_point | 按强度 0–6 区的负荷占比，环形 | 时间与负荷两个口径分两张图 |
| 训练状态卡 | 状态/体能/疲劳 + 过去四周周跑量与周负荷均值 + 备赛调整建议 + 完全恢复/减量50%/减量20% 三种恢复时间 | 结论卡直接给"还能练多重"，恢复给三档 |
| 当前跑力 + 最新记录卡 | 跑力数值 + 超越百分比 + 即时跑力与变化量 | 大数字 + 百分位 + 单次变化，评能力 |
| 成绩预测表 | 全马→1.6km 各距离预测时间 | 预测做成距离-时间卡，不埋在文字里 |
| 配速区间表 / 心率区间表 | 6 个配速区、5 个心率区上下限 | 课表配速锚点直接查表 |
| 跑力分析 | 各距离竞赛跑力，列表/图示切换 | 展示模型的距离差异，结合比赛背景解读 |
| 周期性训练分析 | 近30/90/180天 + 周期/比较切换：跑力变化、训练趋势、各强度区间、各强度负荷、步频/步幅/触地按强度分区表 | 技术指标按强度分区呈现，不做全局平均 |

**Garmin Connect（connect.garmin.cn）**：首页卡片流 + 报告中心双结构，图表用 Recharts（SVG）绘制。

| 页面 | 展示内容 | 借鉴点 |
| --- | --- | --- |
| 首页 | 重点关注卡（睡眠分数、身体电量）、周活动时长柱图（含"过去 4 周"点阵）、概览卡（静息心率迷你线、强度活动时间 vs 周目标、步数 vs 目标线、热量消耗运动/静息堆叠）、今日活动卡（迷你轨迹图）、赛事/教练/挑战 | 恢复指标和训练量并列在首屏；每个指标都带对照值（目标/近期） |
| 报告中心 /app/report | 左侧指标树（所有活动/跑步/骑行/游泳 × 各指标），顶部时间范围切换（当前/4 周/6 个月/1 年），周柱图 + 活动明细表 | 报告必须可按时间窗对比，明细表兜底 |
| 训练状态 | "当前"视图 = 状态结论（如"效率不佳"）+ 训练负荷重点判语 + 三张因素卡（最大摄氧量+评级 / 短期训练负荷+判语 / 训练负荷重点）；"4 周"视图 = 3 联共享时间轴的趋势折线（VO2max、短期负荷、总负荷） | 结论前置：先一句判语，再因素卡，再趋势图 |
| 比赛预测 | 5K/10K/半马/全马四张时间卡 | 预测 = 距离-时间卡片 |
| 最大摄氧量 | 大数字 + 评级徽章 + 性别年龄组百分位 + 趋势折线（含个人历史区间） | 能力指标 = 数值 + 评级 + 百分位 + 趋势 |
| 训练准备程度 | 当日分数 + 组成因素 | 恢复指标当日可用 |

**两家共同规律（按任务与数据适用时参考）**：

1. 结论永远前置（Garmin 训练状态页第一行就是判语；RQ 状态卡第一行就是"状态/体能/疲劳"）。
2. 有可靠、可比的目标、近期均值、百分位或 PB 时提供对照；无对照时标明暂无，不臆造。
3. 长期看趋势折线、构成看堆叠/环形、对比看双列卡或哑铃、明细看表——图型与问题类型绑定。
4. 综合训练报告中，恢复和训练量可同屏；专项统计按用户问题选择维度，缺失数据标明暂无。
5. 预测、评级这类"平台观点"要标注来源平台，两平台观点分歧时各自展示并归因。

## 版式参考（按问题和数据调整，不是固定模板）

**日档（一次活动也能成页）**：页眉+结论横幅 → 活动指标卡×4（vs 近期均值/PB + 迷你线）→ 配速-心率逐点曲线 → 分段剖面 → 心率区间环形 → 近 10 次小柱图 → PB 差值卡 → 恢复卡 → 深色结论块（≤3 条）。

**周/月/年**：页眉+结论横幅 → 指标卡×4（vs 对照期）→ 周期跑量大图（柱状+均值虚线）→ 强度周分布堆叠 → 负荷三视图 → 能力双线 → 预测 vs PB → 双源对照表 → 深色结论块。

**备赛/复盘**：周档基础上，加各强度配速表（课表锚点）、月历热力、taper 进度（目标 vs 实际跑量）。

颜色之外用文字或形状区分系列；缺值断线，不连成假趋势；零训练与缺数据区分。

**卡片配对**：交互页网格里混排整行卡（`span 2`）与半宽卡时，半宽卡按行成对占格；半宽卡数量必须是偶数且相邻排列，否则整行卡会挤到下一行、原行留白。把任一卡从半宽改成整行后，后续所有卡的配对都会变，必须重排顺序而不是只改一个卡；移动端单列布局不受影响。

## 框架和交付

- **Apache ECharts（默认）**：交互式 HTML 多图仪表盘一律用它；把本 skill 的 `assets/echarts.min.js` 整体内联进报告，file:// 离线可开。https://echarts.apache.org/en/
- **Plotly / Chart.js**：仅当用户明确指定时使用。https://plotly.com/javascript/basic-charts/ 、https://www.chartjs.org/docs/latest/general/accessibility.html
- **原生 SVG**：无 ECharts 资产或需要极轻量单图时的后备。

报告 HTML 的引用方式：`<script>${ echarts.min.js 内容 }</script>` 后跟各图初始化脚本；初始化用统一主题（色板见设计规范）。先检查宿主已有库与预览能力，再决定交互页面或静态图；不假设网络与 CDN 可用。训练健康数据只写入用户的报告，不上传第三方服务；交互 HTML 含完整原始数据，分享前提醒用户检查。

`scripts/render_report.py` 是不依赖第三方库的基础柱状图后备方案，不是默认模板；把核实数值整理为 `examples/sample.json` 结构后运行 `python3 scripts/render_report.py input.json output.svg`。不得把样例当用户数据。
